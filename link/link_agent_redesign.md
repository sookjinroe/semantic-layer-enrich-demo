# Link 에이전트 설계 (신호 기반, 2-에이전트 파이프라인)

## 0. 토대 — 왜 Link이고, 언제 Link하나

Link의 존재 이유는 하나다: 사람이 **비즈니스 언어로** 데이터를 찾을 때("연체된 대출 보여줘", "세금면제율이 뭐야?") 그 말이 어느 컬럼을 가리키는지 잇는 것. 즉 Link는 *비즈니스 개념(Term) ↔ 물리 자산(Column)*의 다리다.

그래서 **링크가 가치 있는 시점 = 누군가 그 개념을 부를 일이 있을 때**다. 이 한 문장이 설계 전체를 가른다:

- **개념의 경계는 물리 형태가 아니라 사람이 부르는 방식이 정한다.** `연체여부`(Y/N)와 `연체일수`(숫자)는 타입이 다르지만, 사람은 둘을 "연체"라는 한 개념으로 부른다. 타입 차이로 쪼개는 건 *형태*를 보고 *개념*을 놓치는 것이다.
- 그 "부르는 방식"이 사는 곳은 DB 구조가 아니라 **사용(BI 지표명·함께 쓰이는 패턴)** 과 **계보(같은 변환에서 갈라짐)** 다.

## 1. 두 단계, 신호 요구가 다르다

| | Matcher (기존 Term에 연결) | Discoverer (신규 Term 발굴) |
|---|---|---|
| 질문 | 이 컬럼이 *이 Term*에 속하나 | 이 컬럼들이 *무슨 개념*이고 경계가 어디까지인가 |
| 경계 | **이미 주어짐** (Term 정의·허용값·연결자산) | **만들어내야 함** |
| 신호 충분성 | 구조+Description으로 충분. 애매하면 보강 | 구조만으론 경계를 못 그음 — 사용·계보가 필수 |
| 성격 | 판정 → **자동 확정 가능** | 제안 → **사람 검토 전제** |

핵심 비대칭: Matcher는 *답(경계)이 주어진 판정*이라 신호가 충분하다. Discoverer는 *경계를 새로 긋는 행위*라, 경계를 정하는 정보(사용·계보)가 없으면 형태로 추측할 수밖에 없다. 그래서 신규 발굴은 본질적으로 **제안→검토**이고, 신호는 그 제안의 *질*을 높일 뿐 자동 확정으로 끌어올리지 않는다.

## 2. 신호 — 서열이 아니라 재료

신호에 역할을 미리 고정하지 않는다(어느 게 1차, 어느 게 보조라고 박지 않는다). 신호 하나하나는 불완전하다 — 그 불완전함을 **여러 개 겹쳐 종합하는 것이 AI 추론의 일**이다. 신호가 일치하면 확신이 오르고, 엇갈리면 그 긴장이 판단 재료가 되며, 끝내 안 풀리는 잔여 모호함은 검토로 간다. (Render에서 합의한 "신뢰도는 소스 조합으로 미리 정해지지 않는다"와 같은 정신.)

| 신호 | 무엇을 말해주나 | 한계 (그래서 단독 불가) | 비용 |
|---|---|---|---|
| 구조 (컬럼명·타입·FK·도메인) | "이런 컬럼들이 있다"(후보의 존재) | 사람이 뭐라 부르는지·경계는 모름 | 없음 |
| Description (Render 산출) | "이 컬럼이 무엇인가"(개별 의미) | 컬럼 *사이*의 관계는 모름 | 없음(상류 산출) |
| **사용 (BI 자산: 필드·지표·대시보드)** | "사람이 이걸 이렇게 부른다(라벨) / 이것들을 함께 쓴다(공동참조)"(Term 이름·경계). BI 자산이 컬럼을 N:N 참조 → Link가 역방향 조회. 라벨은 모호할 수 있고(dim_07) 그땐 공동참조·계보로 대체 | 신규/이력 없는 데이터는 신호 없음 | 중간(BI API 파싱) |
| **계보 (Lineage)** | "같은 상류·변환에서 갈라졌다"(개념적 친연성) | '같은 데서 왔다' ≠ '한 개념이다' | 낮음(Catalog 내) |

사용·계보는 단독으론 모호하다. 그래서 **함께** 본다 — 그 종합이 경계를 긋는다.

## 3. Matcher (컬럼 단위, 증거 누적 사다리)

1. **국면0 기술 필터(규칙):** CREATED_AT/_UUID 등 SKIP.
2. **1차 판정:** 구조+Description으로 후보 Term과 대조(검색이 근접오답 포함 후보를 올림).
3. **증거 보강(애매할 때만, 비용 낮은 것부터):** `term_detail`(허용값·연결자산) → `fk`(대상 정체) → `usage`(BI 라벨·공동참조 — 매칭 확신을 높이는 보강). 각 증거는 한 번만 요청(이미 받은 건 재요청 무시). usage 보강은 지저분한 데이터에서 유효하나, 그걸 깨끗이 시연하는 케이스(A4)는 이번 데모 fixture엔 두지 않았다 — BI 공동참조가 "정체"보다 "관계"를 말하는 쪽이라 인위적이지 않게 만들기 까다로웠다. usage·계보가 더 또렷이 빛나는 곳은 발굴에서 경계를 긋는 것이다.
4. **출력:** match(Term, 신뢰도) / reject(collision|no_match → 잔여).

신호 충분 → 자동 확정 가능(HIGH). 여기서 사용 신호는 *경계를 만드는 게 아니라 확정을 굳히는 보강*이다.

## 4. Discoverer (교차 컬럼, 신호 종합 → 제안)

1. **사용·계보로 그룹핑:** 잔여를 구조 유사도가 아니라 **"함께 쓰이는가 / 같은 계보인가"** 로 묶는다. 경계를 *처음부터 올바른 신호로* 긋는다 → 사후 재분할(re-partition) 불필요.
2. **신호 종합 판단:** 군집이 가리키는 개념을, 사용·계보·구조·Description을 겹쳐 추론. 기존 Term과 겹치면 link_existing(중복 방지 재검색). Matcher 거부 근거도 핸드오프로 받음(충돌 거부된 Term엔 되돌려 link 금지).
3. **제안으로 출력(자동 확정 아님):** 신호가 일치·풍부 → 근거 강한 제안(상대적 고신뢰). 신호 엇갈림·빈약 → 보수적으로(저신뢰) 검토. **모든 발굴은 사람 검토를 거쳐 확정**된다 — 신규 Term은 조직이 합의하는 것이지 에이전트가 단독 확정할 게 아니다.

### 회복 모드 (둘뿐, 그 외는 종착점)
- **① 증거 누적(인식론적):** "아직 모른다" → 신호를 더 본다(사용·계보 추가). Matcher·Discoverer 공통.
- **② 단위 수정(구성적):** 발굴에서만 발생. 단, **올바른 신호로 그룹핑하면 단위 오류 자체가 거의 안 생긴다** — 그래서 사후 교정(re-partition) 장치를 두지 않고, 경계가 모호하면 *쪼개는* 대신 *검토로 넘긴다*. (구조 신호로 묶던 시절 re-partition이 필요했던 건, 잘못된 신호로 경계를 그어 생긴 사후 패치였다. 신호를 바로잡으니 그 복잡성이 사라진다.)
- **종착점:** 신호를 모아도 경계가 안 서면 candidate → 사람 검토(auto-write 안 함).

## 5. 두 에이전트, 같은 신호 다른 역할

| | Matcher | Discoverer |
|---|---|---|
| 사용·계보 신호의 역할 | 주어진 경계에 컬럼이 드는지 *확정 보강* | 경계 자체를 *긋는 1차 재료* |
| 출력 | 자동 확정(판정) | 제안(검토 전제) |
| 단위 | 컬럼 1개씩 | 잔여 묶음 |

## 6. 프로덕션 확장성 / 데모 경계
- 사용·계보는 프로덕션에선 BI API·Catalog lineage로 수집. 데모는 **mock 신호**로 같은 추론을 실연한다(파이프라인 비용 없이 가치 전달).
- 신규/이력 없는 데이터는 사용 신호가 없다 → 그런 컬럼은 구조·계보만으로 보수적 제안 또는 검토. 정직한 한계.
- 전체 파이프라인(Render·Matcher·Discoverer·검증·Orion)은 길다. 데모는 Matcher+Discoverer 두 국면으로 묶어 보여준다.
