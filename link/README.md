# Link 데모 (신호 기반) — 정답지 & 실행 가이드

> Render의 후속. **Render**가 컬럼마다 Description을 만들면, **Link**가 그걸 입력으로 받아
> ① 기존 Term에 연결(Matcher) ② 못 붙인 잔여에서 새 개념을 **사용·계보 신호로 발굴·제안**(Discoverer)한다.
> render/ 와 섞지 않는다.

## 0. 토대

Link의 존재 이유: 사람이 **비즈니스 언어로** 데이터를 찾을 때 그 말이 어느 컬럼인지 잇는 것.
그래서 **개념의 경계는 물리 형태가 아니라 사람이 부르는 방식이 정한다.** 그 "부르는 방식"이 사는 곳이
**사용(BI)** 과 **계보(Lineage)** 다. 신호 하나하나는 불완전하므로 **여러 개 겹쳐 종합**한다 — 일치하면 확신↑,
엇갈리면 그 긴장이 판단 재료, 모자라면 검토로. (설계 전문: `link_agent_redesign.md`)

**두 단계의 신호 비대칭:** Matcher는 경계가 *주어진* 판정(기존 Term 정의) → 신호 충분, 자동 확정 가능.
Discoverer는 경계를 *만드는* 행위 → 사용·계보가 필수, 그리고 본질적으로 **제안→사람 검토**(신규 Term은 조직이 합의).

## 1. 입력 신호 (fixture)

- `cluster.json` — 21 컬럼. 각 컬럼에 Render의 `verified_description` + `lineage`(upstream·derived_with).
- 사용 신호는 **별도 `bi_assets`**(16개: field/metric/dashboard)가 컬럼을 참조하는 형태 — 실제 Looker/Tableau API 모양.
  필드가 `label`·`sql`로 물리 컬럼을 1:N 참조, 지표는 집계, 대시보드는 필드 묶음. Link는 이 참조를 **역방향**으로 읽는다(컬럼→참조 자산→라벨·공동참조).
- `term_library.json` — 기존 Term 11개(근접오답: 고객등급·여신한도·연체이자·상환방식[CARD]).

> BI 라벨은 깨끗할 수도(세금면제 여부) 모호할 수도(dim_07, 측정값11) 있다 — 후자일 때 Link는 라벨을 버리고 공동참조·계보로 경계를 잡는다(B2).

## 2. 케이스 ↔ 명제 (이 데이터셋이 증명하려는 것)

클러스터는 현실감 있게 크다(매칭 다수가 배경). 아래가 **주인공 케이스**다.

### A. Matcher — 경계가 주어지면 신호는 충분하다
| 명제 | 컬럼 | 보이는 것 |
|---|---|---|
| **A1 깨끗한 매칭** | LOAN_AMT·INT_RATE·LOAN_STAT_CD·CRDT_GRD_CD·CUST_NO | 구조+Desc로 기존 Term 직결. "대부분 그냥 붙는다." CRDT_GRD_CD는 근접오답(고객등급·신용평가)과 구분 |
| **A2 이름충돌 거부** | RPYMT_MTHD_CD | 이름은 `상환방식`과 닮았으나 CARD 도메인 → 거부 → 잔여. "이름 같다 ≠ 매칭" |
| **A3 보강 매칭(term/fk)** | TAX_EXMP_FLG·RSN_CD(우산, term_detail), LOAN.CUST_NO(fk) | Desc로 애매 → term_detail/fk로 굳힘 |

> *usage를 Matcher 보강으로 쓰는 경로는 살아있다*(애매할 때 term_detail·fk에 더해 usage를 한 번 더 보는 것 — 지저분한 데이터에선 BI 라벨·공동참조가 매칭 확신을 높이는 보강이 될 수 있다). 다만 그걸 **깨끗이 시연하는 케이스(A4)는 이번 fixture에 두지 않았다** — "Desc는 애매한데 usage가 특정 Term을 콕 집어 확정"하는 상황을 인위적이지 않게 만들기 까다로웠다(BI 공동참조는 "정체"보다 "관계"를 말하는 쪽이라). usage·계보가 더 또렷이 빛나는 곳은 **발굴(Discoverer)에서 경계를 긋는 것**(B1·B2·B3)이다. APLD_RATE(적용 비율)는 Desc가 모호하고 BI 참조도 없어 매칭이 아니라 약한 발굴 후보로 검토에 간다.

### B. Discoverer — 경계를 만들려면 신호를 종합한다
| 명제 | 컬럼 | 신호 상황 | 보이는 것 |
|---|---|---|---|
| **B1 신호 일치 → 자신 있는 발굴** | DLNQ_FLG + DLNQ_DAYS | 일치 | 연체현황 대시보드 공동참조 + 같은 배치 계보 → 타입 달라도 한 개념(연체). "신호가 합쳐지면 경계가 또렷" |
| **B2 라벨 약해도 관계로 발굴** | CLTRL_TYPE_CD + CLTRL_VAL_AMT | 라벨 약·관계 강 | BI 필드 라벨이 `dim_07`·`측정값11`(쓰레기)이나, 담보현황 대시보드 공동참조 + 같은 평가배치 계보로 묶임 → 이름 없어도 "담보". **Link의 핵심 가치** — 사람이 이름 안 붙여놨어도 관계로 발굴 |
| **B3 신호 엇갈림 → 추론 후 검토** | CRDT_SCR (+CRDT_EVAL_DT) | 엇갈림 | CRDT_SCR은 독자 라벨("신용점수")인데 신용등급과 같은 대시보드 공동참조 + 형제 계보 → 기존 `신용평가`의 확장이냐 신규냐 모호 → 검토 + Orion. *추론의 자리, 실행마다 가장 변동.* EVAL_DT는 BI 참조 없어 더 약함 |
| **B4 명확하나 단독 / 약한 발굴** | BNS_CD · LOAN_EXP_DT · APLD_RATE | 단독·약함 | BNS_CD: 지표("방카슈랑스 동의율") 또렷하나 단독 → 보수적. LOAN_EXP_DT: 약정조건 대시보드 참조 있으나 단독+만기 기준 모호 → 검토. APLD_RATE: BI 참조 없고 Desc 모호(계보만 금리 형제) → 약한 발굴 후보 검토 |

### C. 정직성 — 발굴은 확정이 아니라 제안
| 명제 | 컬럼 | 보이는 것 |
|---|---|---|
| **C1 신호 부재 → 검토 바닥** | CUST_CLF_CD | 사용·계보 전무 + Render-LOW 유입 → 경계 그을 근거 없음 → 지어내지 않고 사람에게 |
| **C2 모든 발굴은 검토 전제** | (Discoverer 전체) | new_term도 "제안"이다 — 자동 확정 아님. 신규 Term은 조직이 합의 |

예시 분포: 매칭 8 · 잔여(발굴 대상) 10 · SKIP 3. 신뢰도·결정은 모델이 신호를 종합해 정한다 — 실행마다 변동 가능(특히 B3). 끼워맞추지 않는다.

## 3. 실행 (`link_harness.jsx`)

실제 Anthropic API(키 불필요, 일시 오류 시 backoff 재시도). 출력은 스크립트하지 않고 fixture(구조·Desc·계보·BI자산)만 공급.
- 좌: 클러스터(컬럼에 BI 표시명 칩 — 모호하면 dim_07 그대로 보임, 신뢰도 색으로 채워짐).
- 우: 국면0 필터 → 국면1 Matcher(`⟳ usage`는 파란 보강 태그) → 국면2 Discoverer(군집의 *묶은 근거* + 개념별 *핵심 신호*).

§2 케이스표와 라이브 결과 대조. 특히 **담보(B2)가 쓰레기 라벨에도 한 개념으로 묶이는지**, **연체(B1)가 한 개념인지**, **신용점수(B3)가 엇갈림으로 검토 가는지**를 본다.
